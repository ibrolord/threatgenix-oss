# ThreatGenix OSS v1.0.2 Release Validation

Date: 2026-07-22

Scope: the self-hosted v1 product described in the public README. This is not a
validation of the hosted product, managed cloud runners, coordinated
multi-repository orchestration, or the separate ThreatGenix v2 customer-pilot
plan.

## Outcome

The release-critical self-hosted journeys pass after three defects found during
the real deployment retest were fixed:

1. The frontend Compose container copied macOS `node_modules` into its Linux
   image and crashed on Apple Silicon. A frontend `.dockerignore` now excludes
   host dependencies and build output, and the OSS hygiene gate protects that
   boundary.
2. The login throttle was hardcoded at `10/minute` per client IP. The secure
   default remains, but self-hosted operators can now configure
   `AUTH_LOGIN_RATE_LIMIT` for shared-NAT and controlled test environments.
3. The dependency audit identified CVE-2026-49452 in WeasyPrint 68.0. The
   release now pins WeasyPrint 69.0, the
   [upstream security release](https://github.com/Kozea/WeasyPrint/releases/tag/v69.0).

The browser run covered account roundtrip, threat-model CRUD, DFD workspaces and
gestures, custom model properties, deterministic threat generation, triage and
audit state, tenant isolation, validation-lab evidence, provider settings,
application review, reporting, and export surfaces.

## Configuration-Dependent Boundaries

- No external provider key was present in the release environment. Provider
  request contracts, BYOK storage/switching, failure redaction, and graceful
  degradation passed, but this run did not certify live behavior for every
  third-party model API.
- Ollama was reachable but had no model installed, so no local model generation
  call was counted as live evidence.
- GitHub archive, pull-request, webhook, and installation-token contracts passed
  in the automated suite. No GitHub App credential was present, so an
  authenticated live repository import was not counted as release evidence.
- The default Compose image intentionally does not bundle every scanner. Four
  installed scanner paths executed against synthetic fixtures; missing tools
  remained explicit skips.
- Open S2 and S3 coverage rows remain in `feature-test-tracker.md`. They are
  known depth or UX gaps, not hidden release-critical failures.

## Launch Claim Boundary

Accurate: ThreatGenix v1.0.2 is an MIT-licensed, self-hosted threat-modeling and
security-review workspace whose deterministic, evidence, review, tenant,
reporting, CLI contract, and local deployment paths passed the release gates
above.

Not accurate: claiming hosted SaaS readiness, universal live-model provider
readiness, bundled managed scanners, autonomous exploit confirmation,
certification, or completed multi-repository orchestration.
